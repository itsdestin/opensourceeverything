# Open Source Everything: full review and plan (Oct 26, 2026)

Five researchers looked at the live site, the code and the data separately: outside tools, search, contributions,
forks, and the site as a whole. This file combines what they found. Nothing here is live. One trial (better ordering
plus device-aware search) is built on the branch `search-scoring`, backed up to GitHub and not merged.

## The big picture in one paragraph

The site is good at **listing** what replaces a closed app. It's weaker at helping a normal person **choose one**, at
letting a normal person **add something**, and at telling them **how projects relate** (forks). Three things also
quietly undercut trust: activity on the boards that looks fake, the site owner's own project marked Verified, and
internal AI-checking notes shown to visitors. Fixing trust and "help me choose" first gets the most value for the least
work. Contributions and forks are bigger builds that come after.

|---|---|---|

Projects not on GitHub count as 0 stars and sink: LibreOffice, GIMP, Krita, Thunderbird. The editors' best-first order in the data is thrown away, so the top pick differs from the editors' in 69 of 104 groups. | The new ordering on the `search-scoring` branch (section 3). ## 2. Help people choose (the site's main job)

- **Half the catalog needs a server.** 220 of 431 projects are "runs on your own server", 59 are developer tools, and
  only 148 are plain apps you install. The site never explains what "your own server" means. Add one help sentence, an
  **"Easy to start"** filter (install it, or use a free hosted version), and default normal visitors toward it.
- **"Help me choose" prompt.** Today's "Copy prompt" is for builders ("compare it with my project"). Add a second one
  for everyone: "Here's the list; I use a Mac, I'm not technical, I don't want to pay. Which should I pick?"
- **Home page:** one line under the title saying why switching is worth it (free, private, nobody can take it away).
  The category chips get cut off on phones.
- **Missing big apps** people will search for: Netflix, Facebook, Snapchat, Pinterest, Grammarly, consumer VPNs,
  antivirus, AutoCAD, Zotero/EndNote, Steam, Microsoft Office as a bundle. Two groups have no alternatives and 15 have
  only one.
- **Arch Linux and CachyOS are marked as fully replacing Windows and Mac**, while their own notes say "for experienced
  users". Mark them "partly", or add an "experienced users" label.

## 3. Search and scoring

**Today.** Search is already strong. On the four sets of test searches, the right answer comes first 92–99% of the
time; the old name-only search managed 0–57%. Where it still misses: wording the data lacks ("poll to find a day",
"let users sign in with Google"), and **device words did nothing**: "calendar for iPhone" showed Android apps first,
and "Chromebook" matched nothing.

**The real problem is ordering inside a group.** The plan promised a cautious rating score ("2 of 2 never outranks 90
of 100"). It isn't built, and there's no "Best rated" sort.

**Built as a trial (branch `search-scoring`):**
1. **A points score for each alternative, with a visible "why it's first" line.**
   - **Does the whole job:** 40 points, or 14 for "partly". This is the biggest factor, so a crowd can never push a
     "partly" above a "fully".
   - **People's thumbs:** up to ±30, counted cautiously, so a few votes barely move it, no votes counts as zero (not
     a penalty), and 90 of 100 beats 2 of 2.
   - **The editors' order:** up to 14, fading as real votes arrive.
   - **Verified:** +10.
   - **GitHub stars:** up to 6. Weak on purpose; projects not on GitHub are no longer punished.
   - **Inactive or archived:** −24, so a dead project never comes first while a live one fits.
   - **"Open core"** (parts are paid): −5.
   - The editors' first pick now comes first in 79% of groups, up from 34%.
2. **Search understands devices.** "Calendar for iPhone" now favours apps that run on iPhone. On 20 device searches the
   top result now runs on that device 20 times out of 20, up from 16. The four existing test sets score exactly the
   same as before.

**What you'd experience:** group pages reorder. LibreOffice first in Documents; GIMP first in Photo editing. Please
look over the top three in the groups you know before this goes live. Votes aren't connected yet; until they are, the
order is fit + editors + Verified + stars, and the "why" line must say "picked by editors", not "people say".

**Next for discovery, best value first:**
- Quietly record searches that found nothing (the words only, no identity) on a mod page. That shows what to add,
  instead of guessing.
- A device filter that guesses your device but stays one tap from "any device".
- "Related groups", and a gaps page ranked by how many people asked.
- "People who left Notion went to…", only once there are 10 or more votes.
- **"Describe what you need" AI search (later, maybe):** Cloudflare's free AI can match meaning rather than words.
  Only worth adding if it beats today's search on a fresh set of test searches written by someone who hasn't seen the
  code. Downside: every search would pass through Cloudflare's AI, so the privacy page would have to say so.

## 4. Contributions, end to end

**Today:** every "Suggest" button opens a **GitHub form**. A robot checks it, a mod adds an "approved" label, the
robot prepares the change, a mod merges it, and it's live in about 2–4 minutes. The robot pipeline is solid. The front
door isn't:

| Who | What happens now | Where they give up |
|---|---|---|
| **Normal visitor, no GitHub account** ("add Procreate") | Search → "Suggest it" → GitHub login wall → make an account → a form → 4+ fields | **The login wall.** Most people quit here, and they're the site's audience. Then the search's "Suggest it" opens the **new group** form instead of "add a closed app". Then required fields they can't answer ("Group", "Category"). They never hear the outcome. |
| **Project owner** | **"Tag my project" was planned but never built.** The closest path is the long "Add a project" form, with "Are you involved?" as the only owner signal and no proof. | No pitch, no "what's different", no way to edit later, no Owner label. |
| **Someone proposing a group, or a split** | A decent "New group" form. A split ("Photo editing should be two groups") has no form, and the robot refuses to apply "something else". | Splits and moves are all manual. |
| **Technical person sending a change** | The data files are generated from other files, and nothing explains which file to edit. The robot's changes don't get an automatic "checks passed" mark. | Confusion, no green check for mods. |
| **AI agent acting for someone** | **Can't submit at all.** The robot only reads issues that carry labels, and outsiders can't add labels. | Dead end. |
| **Mods** | Email per suggestion → read the robot → label → wait → merge (5–6 clicks, two places). | Duplicate open suggestions aren't caught. Failures are silent. **New accounts aren't held** (the 14-day rule isn't applied to suggestions). |

**Also not built from the plan:** "I want this too" counts, "Most requested" on the home page, a Suggestions tab on
the mod page, and the subreddit bot replying to Showcase posts with the matching group.

**The smoothest version: one front door on the voting server.** One "Suggest" box on the site, which sends to the
server; the server opens the GitHub issue on the person's behalf. The site, AI agents and the subreddit bot all use the
same door. The mod robot stays exactly as is behind it. It costs $0 and loads no outside scripts.
- **No GitHub needed to start:** a search miss becomes one field ("Add Procreate? What do you use it for?") with the
  group already guessed. If you're signed in it goes straight through; if not, it waits for a mod, with limits per
  visitor.
- **Duplicate check while typing:** "Already listed as X" / "12 people already asked for this, add yours".
- **"I want this too"** reuses the existing voting, which gives "Most requested" for free.
- **"Your suggestions"** page showing waiting / approved / live / turned down, and why.
- **Tag my project:** sign in with GitHub; if the project sits under your own account that's proof enough, otherwise
  add a one-line file to the project. Then pick groups, see "Before you build", answer "what's different?", and write
  the pitch. It shows as "Owner says".
- **AI agents:** a documented way to submit the same form. Unless a signed-in person backs it, a human confirms with
  one click, so bots can't flood it.
- **Mods:** a Suggestions tab with Approve / Merge into… / Turn down (canned reasons). Approve goes live without a
  second merge step. Later, optionally, auto-approve the safest kind: an open-source license that passes, an account
  over 14 days, and not a duplicate.

**Small fixes worth doing right away:**
1. Send "Suggest it" from a search miss to the closed-app form.
2. Make Group optional, or a pick list.
3. Have the robot check account age and hold new accounts for a mod.
4. Catch duplicates among open suggestions.
5. Flag robot failures with a "needs a mod" label.
6. Post a thank-you with the live link.
7. A short how-to page for people sending changes.

## 5. Forks and project families

**Today:** forks show as unrelated rivals. Forgejo sits next to Gitea (which it forked from, after Gitea went
for-profit) with nothing linking them; Gitea wins on stars. Four Firefox-based browsers appear side by side, with no
way to tell a privacy-tweaked copy from a different browser. Searching "OpenOffice" or "kbin" finds nothing. GitHub's
own "this is a fork" flag catches only 3 of 431 projects, so a person has to confirm relationships, with the robot
suggesting.

**Families already in the data:** Firefox (LibreWolf, Zen, Tor Browser), Chromium (Ungoogled Chromium, Brave), Gitea
and Forgejo, Nextcloud and ownCloud, Organic Maps and CoMaps, OpenBoard and HeliBoard, Cline and Kilo Code, Bitwarden
and Vaultwarden, kbin's successor Mbin, Perplexica renamed Vane, and the Linux distributions built on each other.
**Missing well-known pairs:** OpenOffice, VSCodium, Redis/Valkey, Terraform/OpenTofu, Floorp, Mullvad Browser,
KeePassX.

**Design:**
- **One "family" line per project:** what it came from, and how.
  - **Copy that keeps up** with the original plus changes (LibreWolf).
  - **Split that went its own way** (Forgejo, LibreOffice, Valkey).
  - **Continues a dead project** (Mbin, KeePassXC, Fossify).
  - **Renamed** (Vane).
  - **Built on** (Bazzite on Fedora).
  - **Free edition of a paid product** (GitLab CE).
  - **"Same name, unrelated"**, so the robot stops pairing Simple Keyboard with Simple Mobile Tools.
  - Each claim gives the year, one neutral sentence on why, a source link, and a mod's sign-off.
- **On cards:** "Split from Gitea (2022) · Compare family".
- **A compare page** (for example, Firefox vs LibreWolf vs Zen vs Tor Browser): what each adds or removes, whether it
  keeps up with the original, license, activity, devices.
- **Dead projects** keep their page with a banner ("Development stopped. Continued as Mbin"), and searching the old
  name finds the new one and says why.
- **Votes stay separate per project.** A fork is a different product, and merging votes would let the bigger name
  swallow its rival. Only renames and true successors carry votes over.
- **"Rescue" for builders:** "Before you build" says "X was abandoned; Y continues it". This is the site's
  reuse-before-rebuild mission applied to forks.

**Main risk:** fork disputes are personal (Gitea/Forgejo, Redis/Valkey, kbin/Mbin), and the site speaks for the
subreddit. So the site shows only sourced, neutral facts (dates, license, who runs it), never "better", and keeps the
"Group related projects" toggle off by default so a fork like Zen isn't buried under Firefox.

**Phases:**
1. The family line, old-name search, about 25 pairs filled by hand, and the missing pairs added. About a day.
2. A family section on project pages, dead-project banners, a "possible family" queue for mods, and robot detection.
   A few days.
3. Compare pages, the grouping toggle, automatic "behind/ahead of the original" counts, and a rescue page. A week or
   more.

## 6. Outside tools worth using

All free, and checked live on Oct 26. None of them imports another site's list, which you ruled out; they only refresh
facts about projects we already list.

**Use now:**
1. **Codeberg and GitLab facts.** Both have free public lookups, and ecosyste.ms covers about 2,000 code sites in one
   place. That closes the known gap where the checker can't read projects hosted outside GitHub. About 30 lines in the
   weekly robot.
2. **More from GitHub at no extra cost:** "forked from", fork count and latest release, added to the lookups the robot
   already makes. These feed the forks work.
3. **The official license list (SPDX):** catches license typos, and says which licenses are OSI-approved.
4. **App stores:** Flathub (Linux), F-Droid (Android) and Homebrew (Mac) lookups to back up "runs on" and add "how to
   install" from real store listings instead of a one-time AI guess.
5. **Search-engine data on each project page:** a short invisible description (name, license, devices) that Google and
   AI tools read. Not a script, so it's safe.
6. **For AI agents:** `llms.txt` and one file per group already exist. Two fixes:
   - The group files leave out devices, stars, Verified and inactive, which an agent needs to choose.
   - Add a version number, so agents notice when the format changes.

**Later:** "describe what you need" AI search (only if it proves better on new test searches); an AI-tool connector
(MCP) on the voting server, so assistants like Claude can search the map directly; security scores (OpenSSF) shown
only where they exist; Wikidata for family links; winget for Windows install info; Repology (its data license is
unclear, so ask first).

**Skip:** swapping in a ready-made search library (today's hand-built search already beats them on the tests and
weighs less), anything that loads an outside script (Cloudflare's captcha, giscus comments, web editors), and
heavyweight project-health suites.

## Suggested order

1. **One sitting:** section 1, plus merging the ordering trial after you've eyeballed the top three in groups you know.
2. **Next:** "Help me choose" (section 2), the seven small contribution fixes (section 4), and the robot additions for
   Codeberg, GitLab, licenses and "forked from" (section 6, items 1–3).
3. **Then:** the single suggest box on the server and Tag my project (section 4), and forks phase 1 (section 5).
4. **Later:** forks phases 2–3, agent connector, AI search trial.

## Decisions only you can make

1. **YouCoded's listing:** remove Verified, mark it "partly", or keep it as is?
2. **The editors' notes on the boards:** label them "From the editors", or remove them until real people post?
3. **Suggesting without a GitHub account:** allow it, held for a mod? Pro: most visitors can finally suggest. Con: more
   spam for mods to clear; per-visitor limits and the hold keep it small.
4. **Auto-approve the safest suggestions** (license passes, older account, no duplicate)? Pro: almost no mod work. Con:
   an occasional wrong group goes live until someone reports it.
5. **Default to "Easy to start"** for visitors, or keep showing everything first?
6. **Who wrote the editors' best-first order** in each group: you and esk, or the AI pre-fill? The new ordering trusts
   it fairly heavily until votes arrive.
